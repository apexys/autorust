# Frozen CPU plans (`autorust::freeze`)

`freeze` turns a captured `Jit` trace into a self-contained Rust source file:
the kernels plus a `FrozenPlan` (storage buffers, typed views, and ordered
kernel/copy/host-GEMM steps). The application `include!`s that file, so the
release binary needs neither the scheduler nor `rustc` at run time — only the
precompiled CPU kernels.

The feature is enabled by default (`freeze` implies `backend_rust`). Use
`--no-default-features --features freeze` for an otherwise minimal build.

## What gets captured

Freeze lowers the **realized** work of one `Jit::call_many` / `call`:

```text
model forward (eager, on RUST)
  -> Jit capture: corealized roots, ordered Jit steps
  -> plan::build: StorageSpec / ViewSpec / Step::{Kernel, Copy, Gemm}
  -> emit_to:      a Rust file with `plan()` and `KERNELS`
```

The plan is backend-independent in shape but its kernels are emitted as **Rust**
and compiled with `rustc` at build time. Capture the forward on `RUST` even on
machines where CL/CUDA are available (the example sets
`DEFAULT_DEVICE=RUST` in `build.rs` for exactly that reason).

- Inputs and weights stay external; weights are passed in the same order used at
  capture time.
- A `HostGemm` descriptor is serialised as `Step::Gemm`, so the AOT plan and the
  eager run make the same library/CPU decision.
- A hand-written kernel step (`Step::Host`) is **not** supported: freeze panics
  with a clear message. A CPU capture never emits one today; a GPU-side AOT plan
  would need a runtime that binds raw pointers.

## Build-script flow

A Cargo build script cannot import the library of the crate it is building, so
the model has to live in a separate crate (or, as in
`examples/frozen_vit/`, in an `include!`d module shared by `build.rs` and
`main.rs`). The frozen-ViT example is a standalone package for this reason.

`Cargo.toml`:

```toml
[build-dependencies]
autorust = { version = "0.1", features = ["freeze"] }

[dependencies]
autorust = { version = "0.1", features = ["freeze"] }
model = { path = "../model" }
```

`build.rs`:

```rust
use std::path::PathBuf;

use autorust::engine::jit::Jit;
use autorust::engine::session::Session;
use autorust::tensor::Ctx;

fn main() {
    // The emitted plan is Rust code: capture on the RUST backend.
    unsafe { std::env::set_var("DEFAULT_DEVICE", "RUST") };

    let ctx = Ctx::new();
    let mut sess = Session::new();
    sess.enable_jit();
    let (model, weights, x) = model::make(&ctx);

    let mut jit = Jit::new();
    let _ = jit.call_many(&ctx, &mut sess, |_c, _s| vec![model.forward(&x)]);

    let built = autorust::freeze::plan::build(
        &ctx,
        &mut sess,
        &jit,
        std::slice::from_ref(&x),   // inputs
        &weights,                   // weights, capture order
    );
    let out = PathBuf::from(std::env::var("OUT_DIR").unwrap()).join("frozen.rs");
    autorust::freeze::emit_to(&built, out).expect("emit frozen plan");
}
```

`main.rs`:

```rust
include!(concat!(env!("OUT_DIR"), "/frozen.rs"));

use autorust::engine::session::Session;
use autorust::freeze::{Engine, Frozen};
use autorust::tensor::Ctx;

fn main() {
    let ctx = Ctx::new();
    let mut sess = Session::new();
    let (model, weights, x) = model::make(&ctx);

    let frozen = Frozen::<MyModel>::new(plan(), KERNELS.to_vec(), weights);
    let mut engine = Engine::new(model, frozen);
    let y = engine.forward(x).to_list::<f32>(&mut sess);
}
```

`plan()` and `KERNELS` are generated by `emit_rust`/`emit_to`.
`Frozen::<M>::new` takes the generated plan, the `KERNELS` table and the weight
tensors. `Frozen::new_jit(plan, progs, weights)` is the in-process variant for
a `Vec<RustProgram>`; `examples/vit_freeze.rs` uses the lower-level
`FrozenRunner::new(built.plan, built.progs)` and writes the emitted file when
`FREEZE_EMIT=<path>` is set.

`FrozenRunner::from_fns(plan, kernels)` is the lower-level runner;
`runner.run(&inputs, &weights) -> Vec<Vec<u8>>` returns the realized output
bytes, and `report_profile()` prints the per-kernel table when `FROZEN_PROF=1`.

## Choosing eager vs frozen

`Engine::new(model, frozen)` picks `Engine::Eager` when a CUDA, Metal or OpenCL
device is available and `Engine::Frozen` otherwise (the frozen plan is the CPU
fallback). `engine.is_eager()` reports the choice; `engine.forward(x)` runs the
selected path. Both paths take and return `Tensor`, via `ModuleForward`:

```rust
impl autorust::freeze::ModuleForward for MyModel {
    type Input = Tensor;
    type Output = Tensor;
    fn forward(&self, x: Tensor) -> Tensor { MyModel::forward(self, &x) }
}
```

`ModuleForward` lives in `tensor::nn` and is implemented by the packaged layers
and models, so a built-in model (e.g. `autorust::models::vit::ViT`) needs no
wrapper.

## Performance

The frozen CPU plan is ~0.86 s per ViT-B/16 forward on the 3900X (eager `RUST`
0.65 s); it trades a little steady-state speed for no `rustc` and no scheduler
in the release binary. The host GEMM path takes the DINOv3 ViT-S/16 plan from
21.7 s to 13.9 s per 16 frames and emits 48 `Step::Gemm` entries instead of
generated kernels; see [`PERFORMANCE.md`](PERFORMANCE.md).
